## 1. What is implemented

`core/js/engine/tech-chain.js` (the only engine file changed): `findForcingChain` and `findForcingChainLong` call the new seam `SG.chainSearch.groupedForcing(model, state, ctx, { id, minLength, maxLength, groupLimit, workLimit, fallback })` (finite limits, no unbounded mode; `fallback: true` for `forcingChain`, `false` for the long ID). The policy of S-OD11, exactly:

1. **One bounded grouped attempt per call**: `buildGraph` with at most **4,096 additional nodes** and **one 50,000-unit allowance shared by construction and search**; the search starts at `work = construction` and the counter is never reset. A Finding is published only from a complete graph in which the window minimum is proved; never from an incomplete graph or the best proof seen so far.
2. **Local caps** are `construction-work`, `construction-nodes` and `search-work`. **Only `forcingChain`**, after a local cap and a passed `ctx.check()` of the parent budget, runs the accepted complete **singleton** search (`scanForcing`) with no local limit, on the same window, under the same parent budget and cancellation. Its work is added to the call's.
3. **No fallback** after parent-budget exhaustion (in the construction, the search, before the fallback or inside it), cancellation, an error, a completed negative (a proof below the window included) or an empty window (`stop: 'empty'`). **`forcingChainLong` has no fallback**: a cap is its null with `capHit: 'work'`. A fallback result certifies only the **singleton-graph** minimum (a shorter proof with groups may exist); a complete grouped search certifies the grouped minimum.
4. **Proof domains.** Contradiction and forced proofs start only at a **singleton** (a true group is no permission to place an arbitrary member); a group starts only as a false endpoint start, a target must conflict with every member of an end group, groups are inner nodes and ends. A proof without a group is byte for byte the legacy Finding (triples, legacy `cells`, no `proofVersion`); a proof with a group is `proofVersion` 2 with `cells` the ascending union of all its nodes. Every array of a Finding is a copy.
5. **Record.** The observer record keeps `{ id, work, limit, capHit, retained }` (`work` is the sum of all stages; `limit` is null for `forcingChain` and 50,000 for the long ID) and adds `domain` (`'grouped'`, `'singleton'` or null), `grouped { construction, search, additional, graph, minimum, stop }` and `fallback { entered, work, outcome }`; it is published only on a normal return, never on cancellation or an error. No more than 256 units pass between two parent-budget checks across both stages.

My first draft wrote it as the word `window`, which the Player `ui-contract` suite forbids in engine code (it scans comment-stripped code for `\bwindow\b`). The behaviour is identical; the whole E was recorded again on the final bytes. **The edits of the rename** (listed because the pre-rename file is **not** retained as a source blob and its hash alone, `5002A98C9A21BC7D1E741CD03D2962342F07D4E8C3C35FC849E934DF036CE8F4` in `e-first-run/engine-frozen.txt`, is not a reproducible diff; I do not claim one): in `core/js/engine/tech-chain.js` the value of the stop `g.stop = 'empty'` (now line 1666), the two comments that name the stop values (the `groupedForcing` docblock, now line 179, and the comment at line 1660), the re-wrap of the file's header docblock to at most 110 columns after the longer words; in `core/tests/suites/tech-chain.test.js` the expected record value `'empty'` of the empty-window test (now line 5494).
