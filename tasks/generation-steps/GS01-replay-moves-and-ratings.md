## Goal & business context

Today the generator's **Generation Steps** tab cuts the dig log into fixed batches and rates each batch's board on
the page within 400 ms (`generator/js/ui/player.js:39–42, 512–553`). Steps whose board changes clues or signs,
or whose rating runs out of time, show no score table (the example Classic 9×9 Expert seed 3275974478 shows no
table on steps 11–18 and 20), and the score jumps.

This task builds the data layer of the redesign: a new pure module `SG.replay` that reads the finished result,
turns its dig log into **complete moves** (a symmetric group, an exchange, a sign: never half of one), and
**rates the board after every move once**, with an honest status when a board cannot be rated. Later tasks select
the steps to show (GS02), explain jumps (GS03), run the work in the worker (GS04) and draw it (GS05, GS06).

The user's first requirement is absolute: **the generation algorithm and every puzzle stay bit-for-bit
identical**. This module only reads `result`; it never changes the engine, the result or the dig log.

## Inputs & context

### The result you read (`PuzzleResult`, unchanged)

`SG.pipeline.run(config, onEvent, budget)` returns `{ model, givens (Int32Array), solution (Int32Array), rating,
seed, config, timings, attempts, warnings, digLog }`. `rating` is `{ level, score, hardestTechnique, solved,
empties, techniqueCounts, … }` (`generator/js/engine/difficulty.js:375–380`). `config` holds `variantId`,
`difficulty` (the level **asked for**), `seed`, `symmetry`, `digOrder` (`random` | `rowByRow` | `snake` | `spiral`
| `jumpOne`), `maxAttempts`, `trace`, `variantOptions`. Tests build requests as the page does:
`SG.store.toConfig({ variantId, difficulty, seed: String(seed) })` (it fills every default, including the
variant's options).

`SG.pipeline.toWire(result)` (`generator/js/engine/pipeline.js:291–303`) gives `{ v, model, givens, solution,
rating, seed, config, timings, attempts, warnings, digLog }` (typed arrays kept as they are);
`SG.pipeline.fromWire(wire)` (`pipeline.js:306–330`) rebuilds the model with `SG.model.create` and passes the
other fields through. `SG.model.create` accepts plain arrays for the layout and units.

### The dig log (`result.digLog`, read-only)

Writers: `generator/js/engine/digger.js:360–375` (`accept`, `reject`, `keep`, `pass`), `digger.js:924` (`restart`),
`digger.js:1127` (refinement `reveal`), `digger.js:1362–1370` (local search), `generator/js/variants/greater-than.js:
279–340` (Greater-Than), `generator/js/variants/killer.js:815–821` (rebuilt Killer log). Entries, in order:

| Entry | Meaning |
|---|---|
| `{ op: 'pass', pass, clues }` | a pass starts; `pass` is `'random'`, `'guided'`, `'fallback'` (Stage A again after a restart), `'signs'`, `'signs.minimal'` |
| `{ op: 'accept', cells }` | a symmetric group was removed (its clues cleared) |
| `{ op: 'accept', cells: [a, b], sign }` | Greater-Than: sign number `sign` (index in the `signs` list) was removed; `cells` are its two cells — **do not clear them** |
| `{ op: 'reject', cells, reason }` | a group had to go back (`reason`: `'ambiguous'`, `'techniques'`, `'tooHard'`, …) |
| `{ op: 'reject', cells: [a, b], sign, reason }` | a sign had to stay |
| `{ op: 'keep', cells, score }` | a guided candidate that passed but was not chosen at once; `score` is the generator's limited check score or `null`; **the chosen candidate is also logged as a `keep`** before its `accept` |
| `{ op: 'reveal', cells }` | clues shown again: the downward refinement (no `reason`), or, right after `clear` (Greater-Than), the starting clues |
| `{ op: 'reveal', cells, reason: 'search' }` | the local search restores clues (alone, or right after an `accept`: an exchange) |
| `{ op: 'restart' }` | the final count found a second solution; the generator digs again from the full grid |
| `{ op: 'signs', signs: [[a, b], …] }` | Greater-Than: every sign, `value[a] < value[b]`; first entry of the log |
| `{ op: 'clear' }` | Greater-Than: the grid is emptied before the starting clues are shown |

Unknown ops and entries that are not objects with a string `op` are ignored (as today).

The example's log (Classic 9×9 Expert seed 3275974478, 74 entries) as a reference: offset 0 `pass random`;
1–25 random accepts and three rejects (`techniques`); 26 `pass guided`; 27–41 keeps and rejects; **42 `accept
R1C2 R9C8`** (its `keep` at 37 has score 551; nine other keeps score 45; five rejects); 43–62 three more guided
accepts (52, 58, 62); 63 `pass guided` (the local search); then five pairs `accept` + `reveal search` (64–65,
66–67, 68–69, 70–71, 72–73).

### The move model (`moves(result)`)

1. `model = result.model`, `n = model.cellCount`. `solution` = `result.solution` when it is array-like of length `n`,
   else null. `signs` = the `signs` array of the first `{ op: 'signs' }` entry, or null. `structure` = `'cages'`
   when `model.cages.length > 0`, else `'signs'` when `signs !== null || model.inequalities.length > 0`, else null.
   `finishedAlive` = the ascending indexes `k` of `signs` whose pair `[a, b]` is one of `model.inequalities`
   (`{ a, b }`), or null.
2. `rebuilt` (Killer's rebuilt log, decision Q15 a) is true only when **all** hold: `model.cages.length > 0`;
   `SG.difficulty.bandOf(result.config.difficulty).min >= SG.difficulty.bandOf('expert').min` (the level **asked
   for**, not `rating.level`; catch an unknown level as false); the log is exactly one
   `{ op: 'pass', pass: 'random', clues: n }` followed only by `{ op: 'accept', cells }` entries; and those accepts
   are, in order and cell by cell, the groups of `SG.symmetry.groups(model, result.config.symmetry)` whose cells
   are all empty in `result.givens` (catch a throwing `groups` as false). `randomOrder` =
   `(result.config.digOrder || 'random') === 'random' && !rebuilt`.
3. Every return, including a failure, contains **all MoveModel fields** from steps 1–2; the abbreviated returns
   below only show the fields that differ. No solution → `{ ok: false, reason: 'noLog', moves: [] }`.
   No log (not an array, or empty) →
   `{ ok: false, reason: 'noLog', moves: [m0] }` where `m0` is the solution move below.
4. Walk the log with: `board = Int32Array.from(solution)`; `alive` = every sign index (when `signs`); `pass = null`;
   `signsStarted = false`; `opening = null`; `ctx` = an empty span accumulator; `lastAccept = null` (the last
   accept-based move of the current pass). `m0 = { index: 0, kind: 'solution', phase: 'start', pass: null,
   from: -1, to: -1, at: -1, removed: [], restored: [], sign: null, span: null, values: copy, alive: copy }`.
   `push(...)` appends a move with `values = Int32Array.from(board)` and `alive` = the current alive indexes.
   - `signs`: skip.
   - `pass`: close the opening; close the trail; `pass = e.pass` (string, else null); if it is `'signs'` or
     `'signs.minimal'`, `signsStarted = true`; `lastAccept = null`.
   - `clear`: close the opening; close the trail; `board.fill(0)`; `opening = { from: offset, to: offset,
     cells: [] }`.
   - `reveal`: validate the cells (an array of distinct integers in `[0, n)`, otherwise unreadable). If `opening !== null &&
     !signsStarted`: set those cells to the solution, add them to `opening.cells`, `opening.to = offset`; done.
     Otherwise close the opening, set the cells to the solution, then: if `e.reason === 'search'` and the last move
     has `at === offset - 1`, no `sign` and a non-empty `removed`, **merge**: that move becomes `kind: 'exchange'`,
     `phase: 'search'`, `restored` = the cells (ascending), `to = offset`, `values` = the board; else push
     `searchAdd` (phase `search`) when `reason === 'search'`, or `reveal` (phase `reveal`) otherwise, with
     `from = to = offset`, `at = -1`, `restored` = the cells.
   - `accept`: close the opening. With a numeric `sign`: it must be an integer in `[0, signs.length)` (else
     unreadable); mark it not alive; push `{ kind: 'sign', phase: pass === 'signs.minimal' ? 'signsMinimal' :
     'signs', sign, removed: [], restored: [] }`. Without `sign`: validate the cells; clear them on the board;
     `kind` = `pass === 'guided'` ? (`ctx` has at least one keep ? `'guided'` : `'searchRemove'`) : `'random'`;
     `phase` = `guided` / `search` / `random` accordingly; push with `removed` = the cells (ascending). Both: `from`
     = the offset of the first `ctx` entry (or this offset when `ctx` is empty), `to = at = offset`, `span` =
     `ctx` summarised (Span; `chosen` matches the keeps against this accept's cells); then `lastAccept` = this
     move and `ctx` starts empty.
   - `reject`, `keep`: add the entry to `ctx` (close the opening first for `reject`).
   - `restart`: close the opening; close the trail; `board = Int32Array.from(solution)` (alive signs unchanged);
     push `{ kind: 'restart', phase: 'start', from = to = offset, at: -1 }`; `pass = null`; `lastAccept = null`.
   - At the end of the log: close the opening; close the trail.
   - *Close the opening*: when `opening !== null`, push `{ kind: 'clues', phase: 'clues', from: opening.from,
     to: opening.to, at: -1, removed: [], restored: opening.cells (ascending) }` and set `opening = null`.
   - *Close the trail*: when `ctx` holds entries and `lastAccept !== null`, set `lastAccept.span.trail` to the
     summary of `ctx` (rated, refused, rejected, rejectedSigns, reasons); in every case `ctx` starts empty.
     Entries of a pass with no accept at all are dropped from the counts (they change nothing on the board).
5. **Consistency**: the last move's `values` must equal `result.givens` cell by cell, and its `alive` must equal
   `finishedAlive` (both null without signs); else `{ ok: false, reason: 'mismatch', moves: [m0] }`. An unreadable
   entry gives `{ ok: false, reason: 'unreadable', moves: [m0] }`.
6. Otherwise `{ ok: true, reason: null, moves, signs, structure, rebuilt, randomOrder, finishedAlive }`.

Known shapes: the example has 32 positions (m 0–31): the solution, **22 random moves** (43 cells: 21 pairs and the
centre), **4 guided moves** (m 23–26) and **5 exchanges** (m 27–31). Move 23 has `at = 42` and
`span = { rated: 15, refused: 5, chosen: 551, others: 9, nulls: 0, max: 45, … }`; moves 24–26 together have
`rated` 17 and `refused` 6.

### Ratings (`rateBoard`, the rating plan of `prepare`)

`rateBoard(model, values, options)`:

Initialize **before solving**: count the zero entries as `E`; make the complete default Rating with
`score/level/hardest/P/W/R/V: null`, `counts: {}`, `empties: E`, `reasons: []`, `checks: 0`, `memo: false`.
Every exit fills this same shape (including guard failures); capture the solve budget's actual `nodes`.

1. `budget = SG.budget.create({ nodes: rateNodes })`. `report = SG.logicalSolver.solve(model, values,
   { allowedTechniques: null, collectSteps: false, assumeUniqueness: true, budget })`. A thrown error with code
   `budget.exceeded` → `{ status: 'capped', reasons: ['capped'], score: null, counts: {}, … }` (the interrupted
   solver returns no counts). Any other error propagates (the job then answers an error).
2. `r = SG.difficulty.classify(report, model)`. `E` = number of zero entries of `values`.
3. `report.status !== 'solved'`: status `stuck`, reasons `['stuck']` (or `['contradiction']` for that status), the
   attempted `counts` = `report.techniqueCounts`, `score` null; then count solutions with
   `SG.budget.create({ nodes: countNodes })`: a result of 2 adds `'ambiguous'` to the reasons; a thrown budget
   error adds nothing; 0 adds `'contradiction'` (without duplicating it). Non-budget errors propagate.
4. Solved: if `SG.difficulty.provesUniqueness(r)` and not `forceCount` → `rated`. Else count: 1 → `rated`;
   2 → `ambiguous` (reasons `['ambiguous']`, counts kept as attempted rows, no score); a thrown budget error →
   `unverified` (reasons `['unverified']`, counts kept, no score); 0 → `stuck` with reason `contradiction`,
   attempted counts and no score. Never publish a score for a count of 0. Non-budget errors propagate.
5. `rated`: `score = r.score`, `level = r.level`, `hardest = r.hardestTechnique`, `empties = r.empties`, and
   `P, W, R, V` from `SG.difficulty.breakdown(counts, empties)` (`peak`, `work`, `workTerm`, `empty`).
   `checks = budget.nodes`.

`prepare(result, options)` is a generator function:

1. `mm = moves(result)`; when `!mm.ok`, return `fallback(result, mm.reason)` (yield nothing). If the supplied
   final rating has no finite score, return `fallback(result, 'error')` without rating any position.
2. `N = mm.moves.length`. A memo maps `key(values, alive)` (`values.join(',') + '|' + (alive || []).join(',')`) to
   a rating. **First**, the finished puzzle: when `result.rating.score` is a finite number, put
   `{ status: 'final', score, level, hardest: hardestTechnique, counts: techniqueCounts, empties, P/W/R/V from
   breakdown, checks: 0 }` under the key of (`result.givens`, `finishedAlive`). The finished puzzle is never rated
   again (its own rating can need 123,741 checks: Mega 16×16 Hell 2 seed 12).
3. For `i = 0 … N − 1`: `solution` and `restart` moves get `{ status: 'zero', score: 0, counts: {}, empties: 0,
   hardest: null, P: 0, W: 0, R: 0, V: 0, level: null, checks: 0 }`; other moves take the memo entry (a copy with
   `memo: true`) or `rateBoard(modelFor(alive), values, options)` stored in the memo. `modelFor(alive)` is
   `result.model` without signs, else `SG.greaterThan.withSigns(result.model, alive.map(k => ({ a: signs[k][0],
   b: signs[k][1] })))`, cached per alive set. After each position, `yield { done: i + 1, total: N }`.
4. Build the details view (below), `stats = { positions: N, fresh, memo, zero, checks }` (`checks` = sum of the
   fresh ratings' checks) and return the Analysis.

`analyse(result, options)` runs `prepare` to the end and returns its value. `fallback(result, reason)` **never
calls a solver**, including when the supplied final rating is missing. `moves` = `[m0, mF]` (only `[mF]` when
there is no solution), where `mF = { index, kind: 'final', phase:
'final', from: -1, to: -1, at: -1, removed: [], restored: [], sign: null, span: null, values:
Int32Array.from(result.givens), alive: finishedAlive }`; `ratings` = zero for `m0` and the final rating of step 2
for `mF`. Without a finite supplied score, use `{ status: 'unverified', reasons: ['missingRating'],
score: null, counts: {}, empties: <zeros in givens>, hardest: null, level: null, P: null, W: null, R: null,
V: null, checks: 0, memo: false }`; never fabricate 0 or retry a rating.

Build fallback steps **separately**, not through the ordinary details loop: one solution step when `m0`
exists, one structure step only when both `m0` and the structure exist, and exactly one final step at `mF`.
Do not also display `mF` as a `moves` step. Preserve all analysis metadata; `stats.fresh`, `stats.checks` and
`stats.memo` are 0. In GS01, `views.details` has these conservative steps and `views.compact` remains null;
GS02 supplies an identical compact view and its transitions without invoking the selector. A missing solution
therefore gives just the final/status step. `fallback` = the reason.

**Details view** (`views.details.steps`): the solution step `{ role: 'solution', first: 0, last: 0, position: 0,
phases: [], kinds: [] }`; when `structure !== null` a structure step with the same fields and role `structure`;
one step per move `i = 1 … N − 1` (`role: 'restart'` for a restart move, else `'moves'`; `first = last =
position = i`; `phases: [move.phase]`, `kinds: [move.kind]`); and the final step `{ role: 'final', first: N − 1,
last: N − 1, position: N − 1, phases: [], kinds: [] }`. For the example that is 33 steps.

`toPlainWire(result)` = `SG.pipeline.toWire(result)` copied with every `ArrayBuffer.isView` value replaced by
`Array.from(value)` (recursively). `fromPlainWire(data)` = `SG.pipeline.fromWire(data)` with `givens` and
`solution` replaced by `Int32Array.from(...)` copies. A round trip through `JSON.stringify` / `JSON.parse` must
give the same analysis as the original result (checked below).

### Status semantics (for later tasks; implement the data now)

| Status | Meaning | Score | Rows |
|---|---|---|---|
| `rated` | complete proof, unique (by the proof or by the count) | yes | the proof's counts |
| `zero` | the solution, the structure step, a restart | 0 | none |
| `final` | the finished puzzle: `result.rating` | yes | the Summary's |
| `capped` | the guard ran out (Q18 b: an honest status, no retry) | no | none |
| `stuck` | the solver stopped before completing the board (Q14 a) | no | the techniques it applied, as attempted |
| `ambiguous` | the count found at least two solutions | no | the attempted rows when the solve returned counts |
| `unverified` | the count ran out of its guard, or a fallback has no supplied final rating (`missingRating`) | no | available attempted rows; none for `missingRating` |
